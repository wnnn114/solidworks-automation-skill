# 工程图与报告同步

## 先读报告再确定出图范围

创建工程图前再次阅读原报告，按“明确出图对象、数量、图幅、视图、比例、标注、标题栏、插图位置、文件名称”列出对应关系。模型文件、结构零件类型、工程图数量、题目数量不能直接互相替代。

本次报告正文写“主要工作零件及装配体”，末尾清单概括为“各零件”。最初出齐 32 张后，用户明确要求删掉多余图纸，最终保留 9 张。以后遇到类似措辞，应先结合详细栏目与当前用户指示解释范围；确实无法解决的冲突再询问，不自动照抄本案例的 9 张或 32 张。

用户只要求精简交付时，将不需图纸从交付目录移出，并核对没有保留成果依赖它们；可在交付目录以外留可恢复备份。不能顺带删除零件模型、装配、报告栏目或必要图注。

## 当前用户的表格偏好

不生成孔位坐标表、轮廓线段坐标表、顶点坐标清单等坐标类表格，不以“详见坐标表”替代常规标注。拥挤时先调整图幅、比例、视图和尺寸布局，必要时用局部或剖视表达。确实缺少定位尺寸时应正常标注或指出缺失，不能因为禁表就省略尺寸依据。

装配明细表（BOM）、标题栏和原上机报告的填写表格不在此禁表范围。用户已经删除的表格不要因为旧脚本或模板默认又加回来。

## 原生图纸与关联尺寸

- 按报告与适用制图要求选用实际 GB 图框及投影法。标题栏从当前模型材料和实际身份资料取值，不编造设计者、材料或技术参数。
- 使用真实模型视图、投影视图和剖视，尺寸关联实际边、面或模型尺寸。尺寸文字像正确数字不代表关联正确；保存重开后核对身份、数值及悬空状态。
- 导出原生 PDF，核对对应尺寸文字和版面，再目视检查漏标、重叠、引线、标题栏及剖视。只读导出后源文件及依赖哈希应不变。
- 不因剖视 API 临时失败就简化模型。定位剖切线、选择上下文或重建错误后修复；只有任务允许且表达完整时，才可换用满足要求的视图组合。

### 偏置零件的剖切线

不能用视图中心代替模型中实际孔槽所在截面。本次 SW2026 的视图草图坐标计算为：

```text
图纸点 = 模型点经 IView.ModelToViewTransform 变换
视图草图局部点.xy = (图纸点.xy - IView.Position.xy) / IView.ScaleDecimal
```

读回实际剖切线端点及剖视对象，确认截到预期孔槽。这个公式只针对本次采用的视图草图上下文，其他草图上下文不能直接套用。

删除失败剖视时检查残留的剖切特征和父视图草图线；选线必须设置正确 `SelectData.View`，不能只凭屏幕位置误删别的视图几何。

### 过程零件撑大图面

动画中的条料、制件、孔料可能停在距模具很远的位置，使投影视图包围盒异常。需要隐藏时，仅在工程图目标视图中选择实际 `IDrawingComponent` 并使用图纸隐藏功能；不要抑制源装配组件或改掉动画场景。

隐藏后重新读取 `GetOutline`。本次 `IView.Position` 仍可能保留远处几何所对应的中心；将可见轮廓中心移动到目标位置，用“当前位置 + 目标中心 − 实际轮廓中心”计算，随后重新核对尺寸、序号及注释位置。

剖视标题可能由 `<VLLABEL>`、`<VLSCALEV>` 字段组成，不能只搜索可见的“A-A”。应辨认真实注释对象后移动它，保留字段和默认名称，不用额外自由文字盖住旧标签。

## 装配 BOM 与序号

先将实际组件类型、实例数及用途需求清单相互核对，再生成适合当前装配层级的原生 BOM。需要结构 BOM 时，按任务排除工艺料件；不能把后台组件总数当结构件数。

SW2026 本次 GB 材料模板的“代号”有时是普通列。原生列类型实测零件号 201、序号 202、数量 203；若当前模板未关联，应从本机类型库核对并转换对应列，回读真实类型和各行实际组件，不用填文字冒充自动 BOM。

文件名称与用途分列，名称保留 SW 默认名。材料来自源模型。模板质量列可能在重建后重置关联：报告不要求时可移除该列；要求时必须建立并验证保存重开后仍有效的原生属性关联，不能手填一个暂时显示正确的值。

每个气泡序号须关联真实装配上下文实体并对应 BOM，必要时使用 `GetCorrespondingEntity` 和视图选择上下文。包括被外壳遮住的小件；不要给内部零件手写无关联序号。保存重开后核对每行数量、编号及气泡覆盖，剖视、侧视与轴测都检查实际轮廓外的文字空间。

## 同步用户修改后的报告

1. 以交付目录当前报告和当前工程图为源，比较旧索引以识别改动。用户在交付后删题、改版式或重保存的文档不得被历史模板覆盖。
2. 只读打开修改后的原生图纸，通过 SW 原生导出 PDF，再生成插图；这才是报告附图依据。用户提供的示意截图只用于说明修改意图。
3. 根据图注和实际关系 ID 定位图片。仅需换图时，替换 DOCX 的对应媒体项，保留原文字、表格、图片显示尺寸、节、页眉页脚和关系。不要依赖上一次报告的固定段落号。
4. 如果正文确实提到被删除的坐标表，再局部修正对应说明；没有提及时不为本次更新添加总结或新章节。
5. 比较修改前后文档包内容，确认只有目标媒体项或必要文字发生变化。旧版备份和 QA 文件留在交付目录外。
6. 用当前可用文档技能的渲染流程产生页图并逐页查看。打包渲染器失败时先查日志；本机缺少 LibreOffice 时曾使用 WPS 自有空会话只读导出 PDF 加 Poppler 排版检查，记录替代路径且不保存源文档、不退出用户 WPS。
7. 最后再次检查目标报告未被并发编辑，再将通过核对的候选写回原交付位置。更新版本哈希与附图来源记录，不把“换图成功”宣称为重新完成所有 CAD 阶段。

只修改工程图或报告时，不重新运行旧批处理补回用户删掉的坐标表、扩充已精简的图纸范围，或覆盖现有模型及视频。
